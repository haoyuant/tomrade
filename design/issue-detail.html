TOM-8 Theme token refactor ui

Replace paired Tailwind strings with :root custom properties

Status Doing Priority Urgent KindTicket · one PR Version4 Last write human · 1h ago

Title and body are human-locked. Agents can still read this issue and change its status, but a write to the locked fields is rejected with a typed error rather than merged.

design-system.ts binds roughly forty paired class strings — "bg-white dark:bg-slate-900" and friends. A third theme cannot be expressed through the .dark variant at all, and adding a matcha: prefix to every string guarantees drift the first time someone edits one side of a pair.

What to do

Declare the tokens once, expose them through Tailwind v4's @theme, and let components consume semantic names. Switching a theme becomes a single class swap on <html>; adding a fourth theme becomes one CSS block.

/* before — the pair has to be edited in two places */ card: "bg-white dark:bg-slate-900" /* after — one binding, three themes */ card: "bg-surface"

Acceptance

  • No raw palette values outside the :root / .dark / .matcha blocks
  • Every hover and selected state verified as a foreground/background pair in all three themes
  • Contrast never drops below the rest state; only :disabled may reduce it
  • The existing .theme-transition crossfade still works
